# 资金对账运行手册

更新日期：2026-07-15

## 目标

在 Supabase 免费层内，用小体量持久化记录完成每日资金完整性核对。对账不修改历史账本，只识别差异、分配责任并记录处理依据。

## 覆盖范围

- 入金确认与已确认入金冲正。
- 放款业务单、客户台账和资金账户流水。
- 还款金额组成、计划分配、客户台账和资金账户流水。
- 资金方提现审批与出账账户。
- 资金方收益确认与资金账户流水。
- 客户台账和资金账户流水的逐笔余额连续性。
- 资金账户当前余额、累计流入、累计流出和累计收益。
- 指向不存在业务单据的孤立流水。

## 自动运行

Vercel 免费层每日调用 `/api/cron/daily`。资金方收益结算生成后执行全历史对账，再继续通知和消息重试。

- `CLEAN`：没有差异。
- `DIFFERENCE`：存在差异；只要有 `OPEN` 项，该维护阶段即失败并发送内部告警。
- `FAILED`：扫描本身失败，必须先排查数据库或代码错误。
- `IGNORED`：有明确依据的例外；相同指纹在后续批次继续保持忽略。
- `RESOLVED`：已执行处理；如果同一差异下次仍存在，会重新打开。

## 人工操作

后台入口：`/admin/finance-reconciliation`

1. 使用“立即全量对账”创建人工批次。
2. 按责任域复核原始单据、银行凭证、审计日志和流水。
3. 完成业务处理后标记 `RESOLVED`，并填写凭证或处理依据。
4. 仅对确认无需处理的例外使用 `IGNORED`，说明不能为空。
5. 禁止直接更新或删除 `LedgerEntry`、`FundAccountJournal` 和历史余额快照。

## 只读命令

```powershell
npm run finance:reconcile
```

命令只读取当前数据库并输出 JSON。无差异时退出码为 `0`，有差异或扫描失败时退出码为 `1`，适合 CI、发布检查和人工复核。

需要按每日幂等键持久化批次时使用 `npm run finance:reconcile:daily`。同一天只会保留一个自动批次。

## 部署

首次发布前执行：

```powershell
npm run db:push
npm run health-check
npm run finance:reconcile
```

新增表只有每日批次摘要和差异明细。正常无差异时每天仅新增一条批次记录，适合 Supabase 免费层长期运行。
